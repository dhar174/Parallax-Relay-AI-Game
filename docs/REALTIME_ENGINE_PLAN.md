## Engine choice and ownership

| Choice | Fit for this slice | Cost or limit |
|---|---|---|
| **Python fixed-step simulation, browser Canvas 2D and DOM** | One local authority can run without a browser. It shares the Python provider, accounting and recording boundaries. The simple room needs rectangular surfaces, horizontal input and one jump impulse. | We own contact rules, edge cases and camera-to-sprite registration. Keep geometry deliberately small and gate it with tick-level tests. |
| Phaser Arcade with a thin scene | Platformer bodies, sprite animation and cameras fit the game. Good candidate if the client grows. | An authoritative JS runtime introduces another process and protocol beside Python. Tab timing and two implementations of physics would complicate headless reproduction. A later renderer-only adoption remains possible. |
| Python with Pymunk | A rigid-body solver becomes attractive for slopes, rotating machinery or movable loads. | Native dependencies, lockfile and matrix work, plus contact tuning for exact platformer controls, buy little for this single fixed-geometry puzzle. |

The recommended Python core runs at **60 fixed ticks/s** with integer sub-tile units. Wall time paces the display and limits inference. A delayed paint, a hidden tab or a disconnected spectator cannot start, skip or resolve a simulation tick. Stream committed poses at about 20 Hz plus contact/phase events. The browser can interpolate between two confirmed samples and snap across resets. It may hold on the latest confirmed sample. Contact and impulse events carry tick, position and pose even between pose samples. Test short takeoff and landing cues at different stream/paint alignments, including a fresh takeoff immediately after landing. A brief visual hold can present a contact while the next authoritative position is displayed. The camera, sprite or animation callback cannot decide a collision. If the host falls behind, bound catch-up work per pump and report pacing lag while preserving every simulation update.

## Coordination, schema and two clocks

Each window samples one immutable observation per role at the same tick. Broadcast, negotiate and commit stay recognizable. Calls within a phase are concurrent. Publish public dialogue in roster order after the communication barrier, and make only completed public batches available to later phases. Early final commit replies can produce a **ready** marker for the human spectator. Keep action contents sealed until release. The model request builder never reads readiness, another role's current reply, the spectator stream or a combined world snapshot.

Issue a fresh, opaque request ID per role and phase, bound server-side to a run UUID, monotonic window number, observation tick and phase. Each transport attempt gets a distinct request ID mapping to the same logical slot and a generation known to the host. Replies echo the issued request ID and window. The host assigns role from its request slot. Untrusted fields cannot select a player. Strictly parse bounded JSON, reject duplicate or extra keys and wrong types, and guard the amount parsed. Validate semantics centrally. A first valid current reply seals its slot. An identical redelivery is idempotent, a conflicting duplicate cannot replace a sealed plan, and replies for obsolete runs, windows, phases or superseded attempts are discarded.

Each phase has one monotonic deadline. Central intake stamps and validates the bounded reply in the coordinator's serialized admission step. A current reply is eligible strictly before the deadline. At the boundary the deadline wins. The earlier of run and phase deadlines applies, and global expiry prevents opening or starting a window. Once all slots are sealed or have terminal dispositions, or the deadline expires, close admission exactly once. Missing speech is silence. Invalid/missing action plans yield a neutral window for that role. Refusals get no repair. In an optional retry-enabled profile, only format/transient transport failures may retry inside the original deadline, with the same observation and remaining team reservation; no strategic retry. An otherwise well-formed plan with disallowed parameters, excessive points, sequence length or duration is rejected in full. Geometry-dependent failures (jump in midair, act beyond reach) consume the scheduled command at its tick. Never truncate a plan, roll commands into a later window, or shift another robot's start.

Seal the entire role map atomically. On the next schedulable tick T, install all three programs, emit one `window_started` record with T, and apply ordinal zero of each program. A neutral program starts on T too. Arrival time cannot move an actor. Each new window invalidates old controls. Missing/stale reply notes never update memory. Fatal setup/provider, budget or persistence errors stop the run at an identified checkpoint, with started attempts accounted for. Cancellation cleanup cannot re-open a slot. Reserve the maximum attempts for all three roles before launching any phase. Share identical request instructions/schema between HTTP serialization, reservation and identity. Settle each started attempt once, including timeouts and cancellations, and retain the quote where usage is unknown. Release only unused reservations. Quarantine a cancellation-resistant task from further dispatch to that role until drained and ignore late bytes for all gameplay and accounting. Preserve the paid profile's breaker of three consecutive failed phases for a role. An isolated timeout still allows the other robots to act.

The first offline variant freezes world physics during discussion, retaining even an airborne state. Implement a development comparison switch for continuing neutral physics during inference, feeding identical reply delays. In that variant gravity and contacts can advance while all new submitted controls remain sealed, observations stay frozen, and a terminal event invalidates the pending window. In both modes T is the next actual committed tick. Record the sampled tick, release tick, world drift and measured wall intervals. Reconcile in-flight calls on a terminal or expired run. The product choice stays open.

## Commands to playtest

Default 120 ticks (2 s), 8 action points per robot, 1–4 commands per submission. Use integer tick offsets and half-open intervals. These are independent configurable limits. Expose budget, command parameters and live validation in a local manual control path using the same parser/validator as the models.

| Command | Parameters | Reserved duration and action points |
|---|---|---|
| RUN | direction −1 or +1, 1–90 ticks, jump_at null or an integer from 0 through ticks−1 | Holds horizontal input for ticks. Costs ceiling(ticks/15), plus 2 for an optional single jump edge. |
| JUMP | none | 1 tick, 2 points, one grounded impulse. |
| WAIT | 1–120 ticks | Specified number of neutral ticks, 0 points. |
| VENT, REROUTE, COLLECT | none | 1 tick, 2 points each. PYRA controls coolant, FLUX powers the motor, SPECTRA can recover the optical shard, and FLUX can pick up the energy cell. |

Programs are sequential. Unused ticks are neutral. Releasing horizontal input stops drive, vertical velocity and gravity persist. An airborne robot can cross a window boundary. A dynamic failure never changes later command offsets. Use the same four required wire keys for every command: kind, direction, ticks and jump_at. Unused parameters must be null. Only commit accepts an action sequence. Public phases carry bounded speech. Use named phases broadcast, negotiate and commit in code. Verify the selected providers' offline wire encoders and parsers against this exact shape and cover all implemented adapters with MockTransport.

One illustrative commit response for SPECTRA (the real request ID is host-generated):

```json
{"request_id":"r7-w2-s-commit","window":2,"actions":[{"kind":"RUN","direction":1,"ticks":36,"jump_at":0},{"kind":"WAIT","direction":null,"ticks":6,"jump_at":null},{"kind":"COLLECT","direction":null,"ticks":null,"jump_at":null}],"notes":"Check whether I reached the shard."}
```

**Worked two-window timeline.** Illustrative arrival times are injected wall-clock offsets from when commit opens. Example window numbers start at 1. Initial frozen world state is tick 0, and the first update is tick 1. Offsets below are relative to the single start tick for that window.

The interactive demo's local controller always chooses its next commands from its own observations and the published conversation. ## Room and observation design

Use a separate development scenario with Split Span's horizontal landmarks. Three robots start at columns 2, 3 and 4. PYRA and FLUX can operate the hot motor near column 4. Its retractable deck spans the gap at columns 5–7. The far bank sits half a tile above deck level. SPECTRA can see a shard at column 9. PYRA can vent starting heat 4 to 1 for one coolant, FLUX can reroute for two energy when the resulting heat after adding 2 is at most 4. A hot or out-of-range attempt records a block. Use one tile of horizontal motor reach at deck height, with ground support required. At the far bank, grounded SPECTRA can collect the shard within half a tile. Define extraction as the grounded region within half a tile of column 12 for every robot. The optional cell at column 10 is visible to FLUX and collectible under the FLUX interaction rule. The exit indicator unlocks when the bridge is powered and the shard is recovered. Keep physical landmarks and objective markers shown by the existing PNG truthful, including the exit and any energy cell represented in it. The team checkpoint requires a powered bridge, recovery of the shard and all three grounded at extraction. A raised face blocks walking onto the far bank. Jump timing matters even after the motor works.

Trial constants are 256 subunits/tile, horizontal drive of 16 subunits/tick, half-width 64 and standing height 192. Positive height is up. Apply impulse +20, then gravity −1 each tick before vertical displacement. With no ceiling the height after k ticks is k(39−k)/2 subunits, peaking at 190. The original draft's +24 could clear an unpowered gap from the edge. With +20, even the full 39-tick return to launch height gives only 624 subunits of horizontal travel. The three-tile gap requires at least 768−128 = 640 subunits of center travel from last support to first far contact, and the far bank is 128 subunits higher. This bound applies from the low starting bank to the high far bank. A reverse jump can have more airtime. Exhaust reachable low-bank takeoff positions, measure reverse travel separately, and verify the actual collision trace before accepting the geometry. Tune only this fixture. Columns are centered on their integer label. Gap edges are x=4.5 and x=7.5 tiles. Require positive horizontal overlap for support. Boundary-touch alone cannot supply a fresh jump. Each tick samples all controls, applies eligible VENT before REROUTE, checks grounded jump edges, sets horizontal drive, then sweeps X and Y against solids, resolving the nearest face and breaking ties by stable geometry ID. Resolve post-motion collection, falls and team checkpoint before publishing. The demo must show an early jump hitting or landing short of the raised lip and a well-timed jump clearing it from the same checkpoint. Use the furthest grounded safe checkpoint before the gap as the return point for a fall below −2 tiles. Robots can overlap one another. A fall below the room restores the last safe spawn for the affected robot, cancels its remaining commands for that window and records the failed attempt. A bridge becoming solid must never teleport an actor onto the deck.

The current 850×295 PNG is a horizontal sensor schematic. Map the printed TURN to the sampled window number, and use nearest horizontal column (ties toward the greater column, clamped to the room), with at most a half-tile rounding error inside the playable centers. Use a one-way, per-role projection of the matching real landmarks and quantized horizontal positions at the sampled tick through the unchanged renderer. The newly versioned real-time text HUD supplies own height, velocity, support, the public platform elevations, current action budget and role-appropriate consequences; tell each player explicitly that TURN is the sampled window and the flat floor in the PNG encodes horizontal layout. Use the HUD for elevations and motion. Build this HUD by allowlist. Suppress obsolete turn-based directions/deadlines/scoring text. Thermal, circuit and optical facts still travel only through their proper channels unless a player actually says them. Check baseline bytes at matched states in one locked environment, real-time attachment isolation on all provider wires, and sentinel absence in every other role, retry and history. If the schematic cannot truthfully represent the room, revise the development geometry or present the image change for a separate design decision. Compare old and proposed images in development before any new evaluation freeze. The six held-out rooms stay outside this work.
